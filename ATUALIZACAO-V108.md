# Braveiros 1.0.8 | Gestão de Acessos

## Atualização pelo navegador
1. Faça backup do banco e guarde o commit atual da v1.0.7.
2. No Supabase Braveiros, SQL Editor → New query, execute todo o arquivo `supabase/v108.sql`. Não execute install.sql ou migrações anteriores. Nenhuma conta ou senha é apagada. Perfis com matrícula já ativos recebem estado aprovado; perfis com matrícula inativos são classificados como pendentes, pois não havia distinção anterior entre inativo e aguardando cadastro. Revise essa lista antes de aprovar.
3. No GitHub, branch main, substitua `api/identity.js`, `src/main.js`, `package.json`, `tests/startup.test.js`; acrescente `supabase/v108.sql`, `tests/registration.test.js` e `ATUALIZACAO-V108.md`. Preserve fotos e demais personalizações.
4. Na Vercel, confira se `SUPABASE_SERVICE_ROLE_KEY` existe em Production, além das variáveis `VITE_SUPABASE_URL` e `VITE_SUPABASE_PUBLISHABLE_KEY`. Nunca publique a chave de serviço no GitHub nem em variável VITE_. A API já existente de identidade usa essas mesmas variáveis.
5. Após todos os commits, acione o Deploy Hook main já existente, se necessário. Confirme `braveiros@1.0.8 build` nos logs.
6. Teste com uma matrícula autorizada ainda sem conta (preserve zeros à esquerda) e senha forte. O cadastro retorna ao login; ao entrar a conta ficará aguardando liberação. Admin ou Super Admin abre Administração → Solicitações de cadastro → Atualizar → Aprovar/Recusar. Após aprovação, o colaborador clica Verificar novamente. A recusa mantém a conta inativa; Super Admin pode reativá-la pelo painel de pessoas, se necessário. O painel mostra a última decisão por pessoa e o banco conserva as decisões na tabela br_registration_audit.

## Segurança e limites
Somente funcionários com matrícula autorizada e ainda não vinculada podem solicitar cadastro. A API cria identidade sintética confirmada, sem mensagem de confirmação para endereço fictício. O gatilho SQL cria perfil inativo com papel employee. A aprovação é feita via RPC que valida Admin/Super Admin e aceita somente perfis employee pendentes. Não há elevação de papel pelo fluxo. A matrícula não comprova identidade por si só: confira com RH antes de aprovar. O endpoint público de cadastro deve receber proteção contra abuso/rate limit na Vercel antes da divulgação ampla; não foi configurada infraestrutura externa. O painel possui atualização manual; polling anterior não atualiza enquanto há formulários na tela. O histórico no painel apresenta a última decisão; histórico completo fica na tabela de auditoria. Aviso visual no menu, sem novo push ou e-mail de solicitação. A lista usa a consulta existente de até 1000 perfis.
